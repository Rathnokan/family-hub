## 4. Session 3 design directive — Echo Show 15 first

**The Mission Control surface (and every "room" page off the Command Center Home) must be optimized for the Echo Show 15.**

- Target viewport: **1920 × 1080 landscape**, 15.6" diagonal, viewed from **6–12 feet** while making coffee. Touch as primary input but glanceability is the headline.
- Secondary viewport: desktop browser (same 16:9, but closer). Anything that works at Echo Show distance works closer-up too.
- The Lovelace card historically rendered into a ~400px column. **It is no longer constrained that way on this surface** — Echo Show 15 gives us full landscape real estate and we should use it.

### Concrete layout problem to fix

The current `modes-cc.js` (and any chore list rendered into the Command Center) lays each chore row out full-width: chore name pinned left, points pinned right. On a 1920px display this is unusable — your eye has to cross 1500+ pixels to connect "Vacuum the rug" to "+15 pts." Visually it reads as two unrelated columns of text.

### Three layout directions to explore before writing the Mission Control rebuild

> **Do not pick one of these blind. Build a small design-canvas tweak that lets the family flip between A / B / C on the kitchen Echo Show for a few days, then commit.** Sessions on the Lovelace card are short anyway and the build cost is low.

**A. Persistent right sidebar (currently sketched in `v1-mission-control.jsx`)**
- Center column: mission rows, ~960–1100px wide. Name + points sit close enough to read together.
- Right rail: Intel Alerts (approvals) + Open Ops (claimable) + footer status.
- Pro: matches the v0.6.0 PLAN as written. Sidebar absorbs everything that today is shoved into headers/footers.
- Con: still one tall scroll of chore rows in the center.

**B. Multi-column chore grid**
- Center column becomes 2 or 3 vertical columns of chore "cards" instead of full-width rows.
- Cards are compact: icon + name + assignees + points + GO, no horizontal whitespace.
- Section headers (BREACH, KITCHEN, BEDROOMS…) span all columns; cards flow underneath.
- Pro: maximum density, no wasted horizontal space.
- Con: harder to scan a single category quickly.

**C. Category-as-column ("kanban-ish")**
- Each column is one category (KITCHEN / BEDROOMS / OUTSIDE / …) running top to bottom.
- BREACH gets a leftmost full-height column with red treatment.
- Pro: maps to how families actually think ("what's left in the kitchen?"). Native landscape win.
- Con: uneven column heights look messy if categories are imbalanced. Open question: do BREACH items move out of their category column or stay?

### What the sidebar should hold (regardless of A/B/C)

- **Agent roster filter** — 5 codenamed agent chips, vertical stack at top of sidebar, tappable to filter the main view. Active state shows their theme sigil + accent.
- **Intel Alerts** — pending approvals + redemption requests. Red dot count + 1-line each. Tap → opens approval modal.
- **Open Ops** — claimable tasks (FCFS + multi-claim) with a small badge for subtype.
- **Status footer** — last sync timestamp, "OPS PAUSED" pill if penalty pause is on, family points total.
- Possible additions (ask before adding): weather entity (if `weather_entity` configured), today's calendar count placeholder, recently-completed feed.

### Accessibility rules (carry-over from PLAN §4, restated for emphasis)

- Min tap target 56×56px. GO buttons 60×60.
- Min body font 18px on Home + Chores HQ. Section headers and stats larger.
- Icon + text label for every status (BREACH, MILESTONE, RESETS) — never icon-or-color alone.
- Pre-reader test: stand 8 feet from the Echo Show with Jackson's eyes. Can he tell what to tap?

## 5. Open design questions to resolve in Session 3

These came up during the exploration and need answers before/during the Mission Control build. Surface them in the first commit message or as a checklist at the top of the Session 3 PR.

1. **Sidebar side — left or right?** Right was sketched in v1 because the GO buttons end at the right edge of each row, and the eye finishes there. Left would put the agent roster filter in a more conventional "nav" position. Lean: right.
2. **Where do the agent tiles live on the Command Center Home?** Currently they're a horizontal strip at the top. On Echo Show 15 they have a lot more room — should they become a vertical sidebar there too, for consistency with the room pages? Or stay horizontal on Home and sidebar on rooms?
3. **BREACH treatment in the multi-column layouts (B and C).** Inline with category (matches reality — the breached chore is still a Kitchen chore) or pulled out into a dedicated BREACH section/column at the top/left (matches urgency)?
4. **Lovelace card breakpoint.** The same code currently renders into a Lovelace card column on bedroom Echo Shows (5/8) too, not just the kitchen 15. What's the breakpoint where the sidebar collapses? Provisional: hide sidebar below 1100px viewport width, push its contents into a modal accessible from the header.
5. **GO button — single-tap or confirm?** Today a tap submits for approval (or self-reports). For the Echo Show, is a single tap enough or do we want a tap-and-hold to avoid accidental completions from kitchen wipe-downs? Lean: single tap with 4-second "tap to undo" toast.
6. **Penalty-accruing flag.** When `daily_penalty_after_days` is firing, the row gets a red "ACCRUING −Npts" badge. Where does it sit — replacing the points medal? Beside it? Above the row?

8. After backend changes: reload integration → hard refresh → call `force_daily_tick` from Dev Tools → Services.

### Things to be careful of (from architecture decisions in NOTES.md)

- Single JSON file at `/config/family_hub_data.json` — never touched by code updates. Read-only for code review purposes.
- Event listeners attached **once** in `connectedCallback` via AbortController — never in `_doRender`.
- Dirty-check uses `last_updated`, not `last_changed`.
- `_doRender` appends the modal as a separate DOM node so background re-renders can't destroy open modals.
- No "overdue" language on recurring chores. "BREACH" is reserved for genuine post-reset state.
- Ghost instance rule: `CHORE_TYPE_ASSIGNED` chores with no `assigned_to` never generate task instances.
- CSS z-index on themed pages: never use `.fh-XX-page > * { position:relative; z-index:N }` — use named selectors. (This bit us in S5.)
- Kid mode is a separate render path, not a CSS override. (PLAN §3.3 doesn't say this; NOTES does. The renderer is `renderKidMode()` in `themes/_shared.js`.)
